## 1. S0:ログイン / 新規登録

### 1.1 項目

| 項目 | 種別 | 必須 | バリデーション |
|------|------|------|----------------|
| メールアドレス | text input | ○ | 形式チェック(`xxx@yyy.zzz`)、未入力エラー |
| パスワード | password input | ○ | 8文字以上(Part2 §3)、未入力エラー |
| パスワード確認(新規登録時のみ) | password input | ○ | パスワードと一致すること |

### 1.2 動作

- ログイン/新規登録はタブ切り替えで同一画面内に配置
- 送信ボタン押下時にクライアント側で上記バリデーションを行い、NGならフィールド直下にエラーメッセージを表示
- サーバーエラー(`EMAIL_ALREADY_EXISTS` 等)はフォーム上部にエラーメッセージ表示
- ログイン成功 → S1へ遷移

## 2. S1:ホーム / レベル選択

### 2.1 項目

- レベル選択ボタン:400 / 600 / 800 / 900+ の4つ。各ボタンの下に**New/Learning/Reviewの件数バッジ**を表示(`GET /api/review-summary`、Part2 §2.7)
- ログアウトボタン
- 「単語一覧を見る」ボタン(S4へ)

### 2.2 動作

- 画面表示のたびに`GET /api/review-summary`を呼び出し、レベルごとの件数バッジを更新する
- レベルボタン押下 → `GET /api/words?level=xxx` を呼び出し、10問分の単語セットを取得してS2へ遷移
- 取得件数が0件の場合はボタンを無効化(または「準備中」表示)

### 2.3 クイズセッションの考え方

- 1レベル選択 = 1セッション = 10問(該当レベルの単語のうち①復習期限切れ→②新規→③期限内、の順に優先して抽出。Part2 §1-3・§2.4)
- 10問終了後はS1へ自動的に戻る(結果画面(S3)は各問ごとのオーバーレイであり、10問通しのサマリー画面は初期版では設けない)

## 3. S2:クイズ画面

### 3.1 項目

| 項目 | 種別 | 必須 | バリデーション |
|------|------|------|----------------|
| 例文表示 | テキスト(読み取り専用) | - | - |
| 解答入力欄 | text input | ○ | 未入力での送信は不可(ボタン押下時にクライアントでチェックしエラー表示) |
| 解答ボタン | button | - | Enterキー押下でも送信可 |
| ヒントボタン×5 | button(トグル) | - | 定義 / 類義語 / 発音 / シャッフル / イラスト。押下順・タイミング自由 |
| 使用済みヒント数表示 | テキスト | - | 「ヒント使用:2/5」のように表示 |
| 進捗表示 | テキスト | - | 「3問目/10問」のように表示 |

### 3.2 入力欄の扱い

- 半角英字以外の入力(数字・記号・日本語など)はそのまま送信可とする(誤入力も類似度判定の対象とし、フロント側で弾かない。空欄のみクライアントバリデーション対象)
- 大文字/小文字は区別しない(Part1 §1.1)

### 3.3 ヒント使用の記録

- 押下したヒントの種類をクライアント側で `Set` として保持し、解答送信時に `hintsUsed` としてAPIへ送る(Part2 §2.5)
- 一度開いたヒントは閉じても「使用済み」の扱いは取り消されない(ペナルティは開いた時点で確定)
- 発音ヒントはWeb Speech APIで単語を読み上げる(基本設計書 §1)

### 3.4 解答送信

- 解答ボタン押下(Enterキーでも可) → `POST /api/quiz/answer` を呼び出し、結果をS3(オーバーレイ)で表示
- 通信エラー時はオーバーレイでエラーメッセージを表示し、再送信ボタンを出す
- 解答送信後、解答入力欄と解答ボタンは無効化する(次の問題(S2)に進むまで再送信不可。Enterキー連打による二重送信を防止するため)
- 解答送信と同時に、実際に使用した/しなかったに関わらず**5種類のヒントすべて**を表示する(押下順に依存しない後出し全公開。使用済みヒント数の集計・ペナルティ計算は解答前に押下したヒントのみを対象とし、この後出し表示による影響は受けない)。表示先はS2画面内ではなく**S3結果オーバーレイのカード内**(次回復習日の下、次へボタンの上)。S3オーバーレイは画面全体を覆うため、S2側の`#hint-content`に表示すると隠れて見えなくなるための対応。ヒント表示エリアは縦方向にスクロール可能とし、次へボタンは常に画面内に表示される

## 4. S3:結果表示(S2内オーバーレイ)

### 4.1 表示項目

| 項目 | 内容 |
|------|------|
| 正誤 | 「正解!」/ 「不正解」 |
| 入力した単語 | ユーザーが入力した文字列をそのまま表示 |
| 正解単語 | 不正解時のみ表示(正解時は入力欄と同じなので省略可) |
| 類似度% | 数値+簡易表現(例:「95%(おしい!)」/ 「40%」) |
| 評価・次回復習日 | 「評価: Good ・ 次回復習: 7/7 13:21」のように表示(Part2 §2.5の`ratingLabel`・`dueAt`) |
| ヒント全表示 | 定義・類義語・発音・シャッフル文字・イメージイラストの5種類すべて(§3.4参照)。縦スクロール可能な領域に表示 |
| 次へボタン | 押下で次の問題(S2)へ。10問目の場合はS1へ遷移。ヒント表示エリアがスクロールしても常に画面内に固定表示 |

※ 旧版で表示していた習熟度スコアの増減(「習熟度 32 → 27」等)はv1.1で廃止。習熟度スコアはAnki評価(Part1 §2.6)を経由して次回復習日に反映されるため、解答直後の即時フィードバックとしてはAnki評価ラベルと次回復習日を表示する方針に変更した。累計スコア自体はS4の単語一覧で確認できる。

### 4.2 類似度%に応じた簡易表現(表示用ラベル)

| 類似度 | ラベル |
|--------|--------|
| 100% | 正解! |
| 90〜99% | おしい! |
| 70〜89% | 惜しい |
| 40〜69% | もう少し |
| 0〜39% | ちがいます |

※ 正誤判定はPart1 §1.5どおり100%のみ正解。本ラベルは不正解時の心理的フィードバック用の表示にすぎない。

## 5. S4:単語一覧 / 習熟度

### 5.1 項目

- レベルフィルタ(400 / 600 / 800 / 900+ / すべて)
- 単語リスト(テーブル/カード表示):単語、習熟度ランク、習熟度スコア、挑戦回数、正解回数、最終学習日、**次回復習日**(Part2 §2.6の`dueAt`)
- 並び替え:習熟度が低い順(初期値)/ アルファベット順 / 最終学習日順

### 5.2 動作

- 画面表示時に `GET /api/mastery`(必要に応じ `?level=` を付与)を呼び出す
- 未学習(mastery=0かつattempts=0)の単語も一覧に含める(習熟度ランク「未学習」)
- 次回復習日は「未学習(復習可能)」(dueAtがNULL)/「復習可能」(dueAtが現在時刻以前)/日時表示(dueAtが未来)の3パターンで表示する
- 行クリックで単語詳細(定義・類義語・例文・次回復習日)を折りたたみ表示(初期版では編集不可、閲覧のみ)

## 6. 共通バリデーション・エラー表示方針

- クライアント側バリデーション:必須項目未入力、形式不正(メール)、文字数不足(パスワード)
- サーバー側バリデーションは常にクライアントと同じ基準で再チェックする(Part2 §2.1のエラーコード参照)
- エラーメッセージは日本語で表示(要件定義書 §2:UIの言語=日本語)
