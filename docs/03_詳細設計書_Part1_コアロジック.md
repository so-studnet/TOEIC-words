## 1. 類似度計算アルゴリズム

### 1.1 方式

**重み付きダメラウ・レーベンシュタイン距離**(編集距離の拡張版)を採用する。

- 入力と正解を小文字化して比較する(大文字小文字は区別しない)
- 一方の文字列を他方に変換するための最小コストを動的計画法で求める

### 1.2 編集操作のコスト表

| 操作 | コスト | 例(正解:comfortable) |
|------|-------|------------------------|
| 文字の挿入・削除 | 1.0 | `comfortble`(1文字不足) |
| 通常の置換 | 1.0 | `comfortoble`(a→o) |
| **r ↔ l の置換** | **0.3** | `comfortabre`(l→r)。日本人学習者が混同しやすいため軽減 |
| **隣接文字の入れ替え(転置)** | **0.5** | `comfortalbe`(bとlの前後逆)。惜しいミスとして軽減 |

### 1.3 類似度の計算式

```
類似度(%) = max(0, (1 − 距離 ÷ 正解の文字数)) × 100(四捨五入)
```

### 1.4 計算例(正解:comfortable、11文字)

| 入力 | ミス内容 | 距離 | 類似度 |
|------|---------|------|--------|
| comfortable | 完全一致 | 0 | 100% |
| comfortabre | r/l混同 ×1 | 0.3 | 97% |
| comfortalbe | 隣接転置 ×1 | 0.5 | 95% |
| confortable | 通常置換 ×1 | 1.0 | 91% |
| comfort | 4文字不足 | 4.0 | 64% |
| happy | ほぼ別単語 | 10.0 | 9% |

### 1.5 正解判定・実装場所

- **正解判定:類似度100%(完全一致)のみ正解**とする
- 実装場所:
  - フロントエンド(JavaScript):解答確定時に即計算・表示
  - バックエンド(Java):同一ロジックで再計算し、スコア改ざんを防止

## 2. 習熟度計算

### 2.1 基本ルール

- 習熟度は単語ごとに **0〜100** の整数、初期値 0
- 正解時に加算、不正解時に減算
- 上限100・下限0でクリップする

### 2.2 計算式

```
正解時:  加算量 = 20 × (1 − ヒントペナルティ合計)   ※小数切り捨て
不正解時: 減算量 = 10(ただし類似度80%以上の場合は半減して 5)
```

### 2.3 ヒントごとのペナルティ値

| ヒント | ペナルティ | 理由 |
|--------|-----------|------|
| 定義 | 0.15 | 標準的なヒント |
| 類義語 | 0.15 | 標準的なヒント |
| 発音 | 0.20 | 答えをほぼ聞いてしまうため重め |
| シャッフル文字 | 0.30 | 文字が全部見えるため最も強力 |
| イメージイラスト | 0.10 | 間接的なヒントのため軽め |

- 複数使用時はペナルティを**合算**する(上限 0.8。全ヒント使用でも加算量は最低4点残る)

### 2.4 計算例

| ケース | 計算 | 結果 |
|--------|------|------|
| ノーヒント正解 | 20 × (1 − 0) | +20(5回連続で習熟度100) |
| 定義+シャッフル使用で正解 | 20 × (1 − 0.45) | +11 |
| 全ヒント使用で正解 | 20 × (1 − 0.8) | +4 |
| 不正解(類似度50%) | −10 | −10 |
| 不正解(類似度85%・惜しい) | −10 ÷ 2 | −5 |

### 2.5 習熟度のランク表示(S4 単語一覧画面用)

| 習熟度 | ラベル |
|--------|--------|
| 80〜100 | マスター |
| 40〜79 | 学習中 |
| 1〜39 | うろ覚え |
| 0 | 未学習 |

### 2.6 復習サイクル(Anki/FSRS方式)への変換

習熟度スコア(0〜100、上記2.1〜2.5節)はそのまま維持しつつ、解答1回ごとに**Anki式の4段階評価(Again/Hard/Good/Easy)**へ変換し、[FSRS](https://github.com/open-spaced-repetition)アルゴリズムで「次回復習日時」を算出する。詳細なDB項目・ライブラリはPart2 §1-2を参照。

**変換の基準は「累積の習熟度スコア」ではなく「今回の解答で使ったヒントの量(2.3節のペナルティ合計)」とする。** 累積スコアを基準にすると、新規単語は必ず0からスタートするため初回〜2回目の正解が毎回Againになってしまい(1セッション=別々の単語が主なので実用上ほぼ常時Againになる)、Anki本来の「今回の解答の出来」という意味からずれるための措置。

変換ルール:

| 条件 | Anki評価 |
|------|----------|
| 不正解(今回のヒント量によらず常に) | Again |
| 正解 かつ 今回のヒントペナルティ合計が 0(ヒント未使用) | Easy |
| 正解 かつ 今回のヒントペナルティ合計が 0.01〜0.30 | Good |
| 正解 かつ 今回のヒントペナルティ合計が 0.31以上 | Hard |

備考:
- 不正解時は「今回思い出せなかった」という事実を優先し、常にAgainとして扱う。
- Good/Hardの境界(0.30)は、軽いヒントを1つ使った程度(定義0.15・類義語0.15・発音0.20・イメージ0.10の単独、または軽いもの2つの組み合わせ)までをGood、それを超える組み合わせ(例:定義+シャッフル=0.45)をHardとする目安。
- 習熟度スコア自体は引き続き2.1〜2.5節どおり計算・保存し、S4の単語一覧画面のランク表示に使う。Anki評価はそれとは別に「今回の解答の出来」を表す指標として、次回復習日の算出にのみ使う。
- 出題時は「復習期限が過ぎた単語(Learning/Review)」を最優先し、次に「未学習の新規単語」、最後に「復習期限内の単語」で埋める3段階の優先度とする(Part2 §2.4参照)。

## 4. 決定事項(確認済み)

- 正解判定は**完全一致(類似度100%)のみ正解**とする(2.4節・本文どおり確定)
